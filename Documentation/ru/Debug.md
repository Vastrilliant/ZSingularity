# DEBUG

Раздел Debug — это просмотрщик собственного `stdout`/`stderr` процесса в реальном времени, то есть того же потока, в который пишут все вызовы `NSLog`; логирование самого tweak записывается в этот поток через макрос `ZLog`. Он не создаёт строки журнала самостоятельно, а захватывает и отображает уже существующие.

Этот обходной путь необходим, чтобы избежать повреждения логов при прямом чтении NSLogs в iOS18+.

## Syslog

Захват работает путём перенаправления файловых дескрипторов `stdout` и `stderr` процесса в pipe, что позволяет читать каждую записанную строку сразу после её появления. Исходные дескрипторы сохраняются, а каждая строка сразу записывается обратно после чтения, поэтому обычное поведение логирования процесса не меняется из-за открытия просмотрщика. Любой другой инструмент, читающий `stdout`/`stderr` (например, консоль устройства или debugger), по-прежнему видит тот же вывод.

## Debug mode

Удержание **Syslog** примерно одну секунду переключает его в режим **Debug**. Просмотр логов сужается до строк, содержащих собственный лог-тег этого tweak, отфильтровывая логи игры и всё остальное, использующее `stdout`/`stderr` процесса. В результате отображаются только сообщения, созданные этим tweak.

## Blacklisted keywords

Поле **Blacklist keywords** позволяет полностью скрывать определённые шумные строки, вместо того чтобы просто прокручивать их. Введите один или несколько терминов через запятую и нажмите return для добавления. Каждый термин сопоставляется с каждой строкой лога как подстрока без учёта регистра.

Термин в чёрном списке:

- Не позволяет будущим совпадающим строкам попасть в buffer.
- Сразу удаляет уже находящиеся в buffer совпадающие строки после добавления; это не ограничивается фильтрацией нового вывода.
- Сохраняется после перезапуска вместе с другими настройками tweak до момента удаления.
