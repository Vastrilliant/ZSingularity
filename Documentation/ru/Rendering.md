# RENDERING
## Render Scale

Масштаб разрешения рендеринга игры.

Значения находятся от 0 до 1.00. В собственном меню настроек игры доступны только следующие пресеты:

- Low = 0.50
- Medium = 0.75
- High = 1.00

Учтите, что снижение Render Scale во время игры редко приводит к значительному уменьшению использования памяти — для полного применения изменения необходимо перезапустить игру.

## Battle RS 

Сокращение от **Battle Render Scale**.

Используя `isBattle=1`, ZSingularity может определить, идёт ли бой, и снизить разрешение до указанного значения.

## AP RS Mult

Сокращение от **Adaptive Performance Render Scale Multiplier**.

Это альтернативный метод render scale, главным образом используемый Android (AOS) портом игры. Он работает через систему Unity Adaptive Performance, а не через обычный engine render scale pipeline.

Значения находятся от 0 до 2.00 и умножают render scale, который Adaptive Performance выбрала бы самостоятельно.

Установка любого значения, кроме 1.00 по умолчанию, автоматически включает Adaptive Performance, поскольку multiplier не действует, пока Adaptive Performance активно не управляет render scale.

**ПРИМЕЧАНИЕ: эта настройка крайне нестабильна. Не изменяйте значение во время боя — это приведёт к зависанию игры. Также не устанавливайте 0.00, поскольку это тоже приведёт к зависанию.**

## Texture MIP

Внутри игры известна как Texture Mipmap Limit.

mipmap — это предварительно рассчитанная оптимизированная последовательность изображений, сопровождающая основную текстуру. Каждое следующее изображение имеет разрешение (ширину и высоту), ровно в два раза меньше предыдущего. Движок выбирает уровень, который лучше всего подходит текущему размеру текстуры на экране, поэтому удалённым или маленьким текстурам не требуется выбирать изображение полного разрешения.

mipmap limit влияет только на `Texture2D` assets, содержащие сгенерированные mip map levels; такие assets также должны иметь следующие свойства:

```
int m_MipMapsStripped = 0
int m_MipCount = 1+
bool m_IgnoreMipmapsLimit = false
bool m_StreamingMipmaps = any*
int m_StreamingMipmapsPriority = 1± 
```

![Mipmap Example](images/Mipmaps_example.png)

Очень немногие `Texture2D` assets имеют необходимые значения, **поэтому настройка затрагивает лишь ограниченное число текстур** — наиболее заметно 'chain' и 'battle' buttons в battle dashboard.

## MSAA

Также называется **Multi-Sample Antialiasing**.

Это Unity-специфичная внутренняя скрытая настройка, которую Limbus не предоставляет пользователю. Значение по умолчанию — 2x.

**ПРИМЕЧАНИЕ: пока неясно, имеет ли эта настройка измеримый эффект на практике.**

## RT Memoryless

`RenderTextureMemoryless` — оптимизация, позволяющая рендерить в RenderTexture без резервной копии в основной системной RAM или VRAM. Вместо этого Unity временно хранит содержимое текстуры только в on-tile cache memory GPU во время render pass, полностью отбрасывая данные сразу после него.

Это обеспечивает значительную оптимизацию памяти на мобильных устройствах, где VRAM bandwidth и footprint сильно ограничены.

- Off — ни один render texture не помечается как memoryless.
- Depth — depth buffer помечается как memoryless.
- MSAA — MSAA resolve buffer помечается как memoryless.
- Depth+MSAA (Both) — и depth buffer, и MSAA resolve buffer помечаются как memoryless.

ПРИМЕЧАНИЕ: Memoryless RenderTextures полностью недоступны для чтения и записи; такие функции, как `Texture2D.ReadPixels()`, `Graphics.CopyTexture()` и compute shaders, завершатся ошибкой.

Это означает, что Shaders и другие Post-processing effects, зависящие от указанных выше методов, не будут отображаться.

**Для полного применения требуется перезапуск игры; некоторые Textures могут не зависеть от этой настройки.**
