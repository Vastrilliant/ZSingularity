# DEBUG

Debug 섹션은 프로세스 자체의 `stdout`/`stderr`를 실시간으로 보여주는 뷰어입니다. 모든 `NSLog` 호출이 기록하는 것과 동일한 스트림이며, tweak 자체의 로깅은 `ZLog` 매크로를 통해 이 스트림에 기록됩니다. 이 기능은 자체적으로 로그를 생성하지 않으며, 이미 존재하는 로그를 캡처하고 표시합니다.

이 우회 방법은 iOS18+에서 NSLogs를 직접 읽을 때 로그가 손상되는 것을 방지하기 위해 필요합니다.

## Syslog

캡처는 프로세스의 `stdout` 및 `stderr` 파일 디스크립터를 파이프로 리디렉션하여 작동합니다. 따라서 두 스트림에 기록되는 모든 줄을 작성되는 즉시 읽을 수 있습니다. 원래 디스크립터는 보존되며 각 줄은 읽은 직후 다시 기록되므로, 뷰어가 열려 있다는 이유만으로 프로세스의 일반적인 로깅 동작이 바뀌지 않습니다. 장치 콘솔이나 디버거처럼 `stdout`/`stderr`를 읽는 다른 도구에서도 평소와 동일한 출력이 표시됩니다.

## Debug mode

**Syslog**을 약 1초 동안 길게 누르면 **Debug** 모드로 전환됩니다. 로그 뷰가 이 tweak의 자체 로그 태그가 포함된 줄만 표시하도록 좁혀져, 게임 자체의 로그와 프로세스의 `stdout`/`stderr`를 공유하는 다른 모든 로그를 필터링합니다. 따라서 뷰에는 이 tweak이 생성한 메시지만 표시됩니다.

## Blacklisted keywords

**Blacklist keywords** 필드를 사용하면 특정 소음성 로그를 단순히 지나가게 두는 대신 완전히 숨길 수 있습니다. 쉼표로 구분된 하나 이상의 용어를 입력하고 return을 눌러 추가하면, 각 용어가 모든 로그 줄에 대해 대소문자를 구분하지 않는 부분 문자열로 매칭됩니다.

블랙리스트에 추가된 용어는:

- 이후 해당 용어와 일치하는 줄이 버퍼에 들어오는 것을 방지합니다.

- 이미 버퍼에 저장된 줄 중 일치하는 항목도 추가되는 즉시 제거합니다. 새 출력만 필터링하는 것이 아닙니다.

- 제거할 때까지 tweak의 다른 설정과 함께 앱을 다시 실행해도 유지됩니다.
